spanning-tree portfast
The port skips the normal STP listening and learning states
It goes immediately to the forwarding state
This speeds up connectivity for hosts (PCs, servers, printers)
Normally STP takes ~30 seconds before forwarding traffic. PortFast avoids this delay.

spanning-tree bpduguard enable
Block devices from interfering with STP
If the interface receives a BPDU, the switch puts the port into err-disabled
This protects the network from someone plugging in a switch or bridge device
bpduguard and portfast are often used together on access ports (ports connected to end devices).

DTP = Dynamic Trunking Protocol
Cisco Systems proprietary protocol used by Cisco switches to automatically negotiate whether a link becomes a trunk or access port.

Disable DTP and set port as trunk:
switchport mode trunk
switchport nonegotiate
Enable DTP and set it to desirable mode:
switchport mode dynamic desirable

DTP modes
Mode				Behavior
access				Permanent access port
trunk				Permanent trunk
dynamic desirable	Actively tries to form trunk
dynamic auto		Waits for trunk negotiation
nonegotiate			Disables DTP





1. Static EtherChannel
channel-group 1 mode on
No negotiation protocol.
Both sides must be manually forced.

Characteristics:
No checking
No negotiation
Dangerous if misconfigured
Can create loops if opposite side mismatches

Use only when:
connecting to devices without LACP/PAgP support
special situations



2. PAgP (Port Aggregation Protocol)
channel-group 1 mode desirable/auto
Cisco proprietary.

Modes:
desirable
auto

desirable:
Actively negotiates EtherChannel.
auto:
Passive, waits for negotiation.

PAgP compatibility
Side A		Side B		Works?
desirable	desirable	Yes
desirable	auto		Yes
auto		auto		No

Why auto-auto fails:
both wait,nobody starts negotiation



3. LACP (Link Aggregation Control Protocol)
channel-group 1 mode active/passive
IEEE standard (802.3ad / 802.1AX).
Preferred in modern networks.

Modes:
active
passive

active:
Actively sends LACP packets.
passive
Waits for LACP negotiation.

LACP compatibility
Side A		Side B		Works?
active		active		Yes
active		passive		Yes
passive		passive		No



Important Rules
1. Interfaces must match
All ports in the EtherChannel must have identical:

speed
duplex
VLAN mode
allowed VLANs
native VLAN
trunk/access mode
MTU


2. Configure on Port-Channel interface

Do NOT configure VLANs separately on member ports, but only on the port-channel interface.
Member interfaces should mostly only contain:
channel-group 1 mode active



4. STP sees EtherChannel as ONE link

Example:
2 cables bundled = 1 logical interface

Benefits:
no spanning-tree blocking between bundled links
full bandwidth utilization

5. Load balancing

EtherChannel does NOT split one single TCP stream over all links.

Instead:
flows are hashed
different conversations use different links

Example:
PC1 -> ServerA = Link1
PC2 -> ServerA = Link2

Common load-balance algorithms
src-mac
dst-mac
src-dst-mac
src-ip
dst-ip
src-dst-ip

port-channel load-balance src-dst-ip
